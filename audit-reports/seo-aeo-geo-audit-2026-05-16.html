TL;DR — the single-page version

Yander is sitting on a solid technical base (Next.js 16, App Router metadata API, sitemap, schema markup, server-rendered content, font-display swap, no JS-only content) but is shipping with seven critical defects that hurt every page — broken social card images, a host/canonical mismatch (yander.ai in code vs. www.yander.ai in production), title double-suffix on most blog posts, a stale Pulse-era WebSite schema, missing canonical on key pages, missing OG/Twitter images on 4+ commercial pages, and a duplicate <h1> on the blog listing.

Underneath that, the AEO/GEO surface is thin: no llms.txt, no explicit AI-bot allowlist, no FAQPage / BreadcrumbList / HowTo / Speakable schema, generic "Yander Team" author for every blog post (drops E-E-A-T), dateModified === datePublished always (kills the freshness signal), and no AboutPage with named team. About half of the live URLs aren't in the sitemap (the other half are 301-redirected the moment Google fetches them).

The good news: most fixes are mechanical edits to four files (app/layout.tsx, app/sitemap.ts, app/robots.ts, lib/seo-utils.ts) plus one image asset upload. Estimated total fix effort to clear P0+P1: 1–2 days.

Critical issues (P0 — fix today)

SEOTECH1. og-image.png returns 404 — every social share is broken

app/layout.tsx:56 · also referenced from app/(main)/blog/page.tsx:23, app/(main)/changelog/page.tsx, app/(main)/changelog/[slug]/page.tsx, blog post fallback (og-default.jpg)

Every page on the site references https://yander.ai/og-image.png as the default Open Graph and Twitter image. The file does not exist in public/ and returns HTTP 404 in production:

$ curl -I https://www.yander.ai/og-image.png    → 404
$ curl -I https://www.yander.ai/og-default.jpg  → 404

Result: LinkedIn, X, Slack, iMessage, Facebook etc. will fall back to no preview image or a broken thumbnail — on the homepage, on every blog post, every pricing page, every legal page.

ImpactCatastrophic for paid social and organic sharing CTR. Estimated 40–60% drop in click-through vs. a working OG card.

FixUpload a 1200×630 og-image.png AND og-default.jpg to public/. Verify with opengraph.xyz. While you're there, generate per-page OG images for /pricing, /pulse, /pulse-pricing, /compare — Vercel's opengraph-image.tsx convention is ideal here.

SEOTECH2. Host mismatch — code uses yander.ai but production serves www.yander.ai

Sitemap, every canonical, every og:url, every JSON-LD url, recent commit 76d6c0f migrated .io→.ai but kept the bare host

Production behaviour:

$ curl -sI https://yander.ai/         → 301 → https://www.yander.ai/
$ curl -sI https://yander.ai/pulse    → 301 → https://www.yander.ai/pulse
... (every URL redirects)

But the code consistently emits the bare-host version in canonical / OG / sitemap:

sitemap.xml<loc>https://yander.ai/...</loc> × 29 entries canonical (every page)https://yander.ai/... og:url (every page)https://yander.ai/... JSON-LD @id, urlhttps://yander.ai/...

Every URL Google fetches from the sitemap eats a 301. Every canonical points to a URL that redirects to the URL the user is actually on (canonical "self-canonicalize" is broken). This is the single biggest blocker to recovering ranking authority after the .io→.ai migration.

ImpactWastes Googlebot's crawl budget, weakens canonical signal, and creates two competing index entries (bare and www) when third-party sites link to yander.ai.

Fix — pick one of two paths:

  • (Recommended) Configure Vercel to serve yander.ai as the primary domain and 301 www.yander.ai → yander.ai (the opposite of what's happening now). The code already targets bare-host, so no code change needed beyond updating the Vercel domain settings.
  • OR change every https://yander.ai to https://www.yander.ai. Files to touch: app/layout.tsx (5 spots: metadataBase, OG url, OG image, Twitter image, Organization url, WebSite url); app/sitemap.ts (SITE_URL constant); app/robots.ts (sitemap URL); lib/seo-utils.ts (siteUrl default); every per-page canonical hardcode (blog, pricing, pulse, pulse-pricing, integrations, changelog, compare, security, privacy-policy, terms-of-service, dpa, beta-terms, contact-sales — 13 files).

SEO3. Title double-suffix on every blog post: "… | Yander | Yander"

lib/seo-utils.ts:43 — const fullTitle = `${title} | Yander`

AEO10. No llms.txt, no AI-bot allowlist in robots

app/robots.ts · no public/llms.txt

Current robots.ts is one wildcard rule. There's no explicit signal that AI crawlers are welcome (and they're increasingly auditing for this), and no llms.txt for the proposed LLM-discovery standard.

ImpactSome AI engines treat the absence of an explicit AI-bot allow as ambiguous and back off. llms.txt is the highest-ROI 5-minute AEO win available today — adoption is ~15% but climbing, and yander.ai will be cited more easily once AI engines have a structured "what is this brand" file.

Fix (app/robots.ts):

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: '*', allow: '/', disallow: ['/studio/', '/waitlist-confirmation/', '/api/'] },
      // Explicitly welcome AI bots
      { userAgent: ['GPTBot','ChatGPT-User','OAI-SearchBot','ClaudeBot','anthropic-ai',
                    'PerplexityBot','Perplexity-User','Google-Extended','Bingbot',
                    'CCBot','Bytespider','DuckAssistBot','Applebot-Extended'],
        allow: '/', disallow: ['/studio/', '/api/'] },
    ],
    sitemap: 'https://yander.ai/sitemap.xml',
    host: 'https://yander.ai', // declare canonical host
  }
}

AEO readiness deep dive (7/20)

AI engines (ChatGPT, Perplexity, Claude, Gemini, Google AI Overviews) extract content differently from Googlebot. This section evaluates Yander's surface specifically against AEO research benchmarks.

9a. Entity identity

  • Organization schema present with sameAs
  • Brand name consistent across schema and visible content
  • About / team page missing — there is no /about; curl https://www.yander.ai/about returns 404
  • AboutPage schema missing
  • disambiguatingDescription in Organization schema missing
  • foundingDate, address, numberOfEmployees missing

9b. Category membership

  • Homepage H1 is concrete: "The first AI agent that recruits for you" — strong category claim
  • Category statement repeated across pages weak — Pulse page positions Yander as "team performance intelligence", not as a recruiting agent; the two products dilute each other's category claim
  • Vertical landing pages exist partial — /industries/[slug] route exists but unknown how many are populated; none appear in sitemap
  • "Yander is a [category] for [audience]" statement in first 100 words of homepage weak — current opener is poetic; AI engines extract literal category claims better

9c. Content structure for AI extraction

  • All key content is server-rendered (verified via curl)
  • JSON-LD is inlined in <head>, not deferred via <Script>
  • FAQ markup is plain HTML, not FAQPage schema missing
  • Self-contained opening paragraphs partial — blog post intros pass; homepage hero is good; product pages bury the category claim under animation
  • Closing-statement extractability per section partial

9d. Comparison & recommendation readiness
